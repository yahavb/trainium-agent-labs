# Seat-115: v7 runs, the level-1 rule, and kernels run on the chip

Evidence from liuyq's seat (seat-115) and the team's 4090 desktop, 2026-10-10. Logs are in
`analysis/logs/` (folders below). Three standards are used and named in every table:

- **simulator**: scores 1.0 in the NKI 0.6.0 CPU simulator on the checker's shapes (what the agent sees);
- **builds**: the full trn2 build (`check/compile_solves7.py`: neuronx-cc to a NEFF, then birsim, the
  compiler's instruction-level simulator) succeeds and matches NumPy. The verdict's own compile step only
  lowers, and passes kernels the full build rejects (level 1's per-channel reduce, the d11 level-2 kernel);
- **chip**: the kernel run on a NeuronCore of the seat's Trainium2 (`check/device_check.py`; in nki 0.6.0 a
  `@nki.jit` call with NumPy arrays compiles and runs it on the device), compared with NumPy at nkibench's
  tolerance. The model server was stopped for these runs (it holds all four cores).

## The level-1 rule (gate_nki.py, 89417dd; V7.md "The level-1 fix")

`logs/task15_4090_l1rule/`: the 4090 generated, both conditions at the same time on one server, levels 1
and 2, 10 runs each; every distinct solve and every kernel the rule held was full-built on seat-115
(`l1fix_solves.log`, `l1base_solves.log`, `l1fix_held.log`). Runs with a kernel that **builds** and matches:

| | level 1 | level 2 |
|---|---|---|
| v7 + rule (`l1fix`) | **4/10** | 5/10 |
| v7 (`l1base`) | 0/10 | 8/10 |

- Level 1: in all 4 runs the round-0 kernel was held, the next round pasted the rewrite (16 of 16
  next-round samples contain it), and it built. Without the rule: 0/10 here and 0/20 in the rehearsal's
  tasks 12-13, so 4/10 vs 0/30 (Fisher p = 0.002).
- Level 2: the rule fired in one run, only on kernels that fail the full build; the 4 failed runs never
  reached a full score, so 8 vs 5 is run-to-run variance, not the rule. All 8 held kernels fail to build.
- `RESULTS_4090.md` is the desktop's own summary (simulator counts). The two console logs had the
  desktop's home directory replaced with `~`; nothing else was changed.

**On Trainium** (`logs/seat115_l1rule/`, Qwen served on seat-115, same kit with the rule, 15:50-16:08,
stopped at the freeze): 3 finished level-1 runs, **1 solved** (s1a run 2, on round 0; it builds, matches
in birsim and passes the held-out set 20/20). The rule did not fire in these runs (no attempt at 0.95), so
this run says nothing about the rule; it is the first level-1 kernel generated on Trainium that builds.

**Re-grading.** Every 1.0 in these logs was checked independently by the full build, which writes each
kernel to its own file (so the reused-path bug, ded1ef2, cannot affect these verdicts). The distinct
kernels of d1-d12 and t1 were also re-graded through v7 with a fresh path each (13:30): all scores as
logged. d13, d14, s1a, s1b and the 4090 logs were not re-graded in the simulator.

**Sample variety on the seat.** Identical sample pairs per round: round 0, 1% on the 4090 vs 50% on
seat-115; repair rounds, 54% vs 87%. On seat-115, six identical requests at temperature 1.0 returned six
different answers, so sampling is applied there, but the seat's samples repeat far more than the GPU's,
most of all in repair rounds.
