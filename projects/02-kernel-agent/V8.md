# feedback_v8: v7, plus changes aimed at v7's weak spots

`feedback_v8.py` is one more layer on top of `feedback_v7.py` (see [V7.md](V7.md)). It changes nothing in
v7's files: it patches at import time, like the layers below it. One change is always on; the others are
switches, off by default, and with them off v8 behaves like v7 plus E-div.

**v8.2, the final candidate (16:09):** commit `96a9fc9`, `feedback_v8.py` md5 `c2f81a3628d1252ea5aa719b4e1b08e1`,
switches `TRUNCFIX=1 L1FIX=1 MIXSAMP=1 L2HINT=1 MIX=1`, `SKELETON` off. The versions on the way: v8
(15:45) was `SKELETON=1 TRUNCFIX=1 L1FIX=1`; SKELETON was dropped after it broke level 4
([analysis/taxonomy_versions.md](../../analysis/taxonomy_versions.md)); v8.1 (16:02) added `MIXSAMP=1 L2HINT=1`;
v8.2 adds `MIX=1`. Results and the decision: [PLAN.md](../../PLAN.md) §4 and NOTES §0.

## Run it

v8.2, from this folder, on a seat with the model server up (`/workspace/serve.sh`). The first two
exports are V7.md's "Run it"; the third is v8.2's switches. Replace N with the level.

```bash
cd projects/02-kernel-agent
export NEURON_PLATFORM_TARGET_OVERRIDE=trn2 KERNEL_AGENT_BASE_URL=http://localhost:8000/v1 PYTHONPATH=.:check
export MESSAGES=v5 CARD=category PROMPT1=v2 SAMPLING=qwen REPAIR_PROMPT=restructure GRADE_TIMEOUT=120 \
       GATE=static NKI_VERDICTS=nki_verdicts_LN.jsonl NKI_VERDICT_COMPILE=1 USAGE_LOG=usage_v82_LN.jsonl
export SKELETON=0 TRUNCFIX=1 L1FIX=1 MIXSAMP=1 L2HINT=1 MIX=1
python3 feedback_v8.py --level N --rounds 8 --samples 4 --context 8192 --repeat 5 \
    --log v82_LN.jsonl --verdicts verdicts_v82_LN.jsonl
```

The run prints its switches at the start (`SKELETON=0 L1FIX=1 TRUNCFIX=1 MIXSAMP=1 L2HINT=1 MIX=1`); check
that line against the one above.

## What v8 changes, and why

| change | switch | what it does | the weak spot in v7 it answers |
|---|---|---|---|
| **E-div** | always on | sample 1 keeps the prompt byte for byte; sample k ≥ 2 gets one line, `(attempt k of n, run r)`, appended to the user message. Ties still go to sample 1, so v7's own trajectory is always among the candidates | the seat's server is deterministic: 4 concurrent identical requests at temperature 0.7 come back byte-identical, so `--samples 4` bought one sample per round and `--repeat 5` one run. v7's five level-4 runs were one trajectory replayed |
| **Skeleton feedback** (not in v8.2) | `SKELETON=1` | every repair message that carries code keeps its loops, calls, API names and variable names, but the slices, the tile shapes and the loop counts become `<…>`, with one sentence saying what goes there. Prose, messages without code, and API-name corrections are unchanged. **Compiler-gate messages are left whole** (below) | in v7 the fix for a known error class is code to paste, and the model pastes it: part of the solution comes from the checker. Here the model has to work out the slices and shapes itself |
| **Truncation** | `TRUNCFIX=1` | an answer that ends at the token limit (`finish=length`) is not graded; the next round gets one instruction: "Your previous answer was cut off at the token limit before the code was complete. Reply with a shorter kernel: the code block only, no comments, no explanation." `finish` is logged | v5's request function replaced agent.py's and dropped its `finish_reason` check. In v7's level-1 run 1, three of eight rounds had all four answers cut off; the checker answered "does not parse", which the model cannot act on, and those rounds took 447 s each |
| **Level-1 calls** | `L1FIX=1` | three level-1 errors that v7 answers with a generic sentence get the real 0.6.0 usage (`nisa.memset` / `nl.zeros` instead of `nc_clear`; slicing instead of `nl.reshape`; `nisa.tensor_tensor(op=nl.add)` instead of `+=` on a tile), each name checked with `inspect` on a seat | v7's most frequent level-1 failures |
| **Mixed sampling** | `MIXSAMP=1` | odd samples use agent.py's sampling settings, even samples v7's, so each round covers both | the server answers a given request body with the same text every time, and other settings give other text: level-2 round 0 is 0/20 with v7's settings and 2/20 with agent.py's, prompts byte-identical |
| **Level-2 hint** | `L2HINT=1` | on the errors that come from transposing the whole input at level 2, the feedback adds one sentence restating the task (rows stay put; each row's F1-by-F2 matrix is transposed), with no code | in v7's and the baseline's level-2 repair rounds, 81 of 134 failures were the model transposing x itself; the messages named only the symptom |
| **Fresh attempts** (E-mix) | `MIX=1` | from round 1 on, sample 1 repairs the best kernel with v7's prompt, byte-identical, while samples 2..n get the first prompt again, tagged `(fresh attempt k, round t, run r)`: about 27 fresh attempts per run instead of 4. The best of the round is repaired next, ties to sample 1 | level 2 had only ever been solved in round 0 (0 of 104 baseline and replica repair samples), and v8's level-1 solve came from a near-right round-0 kernel |

Before/after samples of the skeleton messages: [analysis/v8_skeleton_samples.txt](../../analysis/v8_skeleton_samples.txt).

The base also carries liuyq's level-1 gate rule (89417dd, in v7's `gate_nki.py`); it fires on none of the
11 distinct full-score kernels we have ([analysis/gate_l1_check.md](../../analysis/gate_l1_check.md)).

**SKELETON leaves the compiler gate's messages whole.** The gate only speaks after a kernel is correct
on every shape in the simulator, and its code is the model's own lines rewritten for the trn2 compiler:
`nl.divide` as a reciprocal and a multiply, a (rows, 1) column through `tensor_scalar`, and level 1's
per-channel loop as one instruction over all channels (`t[:, window]`). Those slices are the fix: blanked,
the level-1 rewrite becomes `t[<…>]` and the model has only its per-channel form to go back to. On the
4090, the exact rewrite turned 4 of 4 held level-1 kernels into kernels that build and match (4/10 runs vs
0/30 without the rule; V7.md, "The level-1 fix"). So under SKELETON the gate's rewrites are still given
as code; every other code message is skeletonized as described. A SKELETON result is therefore about
v3-v6's messages, not the gate's.
