Installed SDK evidence: `0.6.0+31049202112.g85070674`. `nc_matmul(dst, stationary, moving, ..., accumulate=None, ...)` requires explicit FP32 PSUM destination on Trainium2; `tensor_tensor(dst,data1,data2,op,...)` requires four operands. `sum(x,axis,dtype=None,keepdims=False)` and `max(...)` allocate their return shape internally. Simulator matmul reshapes its MxN result to dst.view_shape; source reshape is not necessary for a reshape exception. These findings were reproduced with tiny independent CPU simulator tests, not Wan hardware execution.

## Hardware profiling plan

The [job workflow](https://github.com/yahavb/wan2-ti2v-5b/blob/0861750070f5413e0ba59f9089b813a4c5d99a62/wan2-ti2v-5b-job.yaml) archives unique run/profile directories, then runs Neuron Explorer view in summary-text and JSON modes and summarizes compiled NEFF sizes. Adapt the order: full CPU functional checker first; select only a verified candidate; confirm this seat's logical core configuration and Qwen/other-process ownership; reserve genuinely unowned compatible cores and the correct LNC setting; confirm Trainium2 compiler target and installed compiler/runtime tools; then compile/run one candidate and retain numerical comparison, compiler artifacts and profile output in a private directory.

No core ownership or device capacity has been established by this review. Do not reuse the Wan resource claim or a seat-266 configuration as evidence for seat-265. Do not displace Qwen. Do not use obsolete nki.benchmark/nki.baremetal examples or compile all generated failures. Explorer command compatibility must be checked locally before future use. CPU simulation traffic/roofline estimates do not establish measured device performance.
