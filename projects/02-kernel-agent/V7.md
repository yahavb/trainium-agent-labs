# feedback_v7: the final agent configuration

`feedback_v7.py` runs their `agent.py` loop (rounds, samples, best-of-round, ledger, the held-out check and
calibration) with the changes listed below. It imports v6, v5, v4, v3 and v2, which sit next to it; each
layer patches `agent` at import time. Seat-115 ran this configuration on the day with the organizers'
original `nkibench.py`; here it grades with this repo's (allocation audit, a fresh file per candidate).

## Run it

From this folder, on a seat with the model server up (`/workspace/serve.sh`):

```bash
cd projects/02-kernel-agent
export NEURON_PLATFORM_TARGET_OVERRIDE=trn2 KERNEL_AGENT_BASE_URL=http://localhost:8000/v1 PYTHONPATH=.:check
export MESSAGES=v5 CARD=category PROMPT1=v2 SAMPLING=qwen REPAIR_PROMPT=restructure GRADE_TIMEOUT=120 \
       GATE=static NKI_VERDICTS=nki_verdicts.jsonl NKI_VERDICT_COMPILE=1 USAGE_LOG=usage_v7.jsonl
python3 feedback_v7.py --level 4 --rounds 8 --samples 4 --context 8192 --repeat 5 \
    --log attempts_v7.jsonl --verdicts verdicts_v7.jsonl
```

- `--level` takes one level; `--all` is levels 1-4. Levels 9-14 are ours (below).
- `--context 8192` is the seat server's max-model-len (`/v1/models` reports it).
- Two verdict files, on purpose: `--verdicts` is agent.py's (confidence, then the held-out set);
  `NKI_VERDICTS` is ours (extra hostile-value cases and the trn2 compiler). Keep the names different.
- Test without a model: add `--offline` (levels 1-4 only; it replays their reference kernels).

## The final configuration

| variable | value | what it selects |
|---|---|---|
| `PROMPT1` | `v2` | first prompt with the exact def line and a block of real NKI functions |
| `CARD` | `category` | one worked example in the first prompt, chosen by the operation's category |
| `MESSAGES` | `v5` | repair messages: v2 + v3 + v4 + v5's matmul tiling message |
| `REPAIR_PROMPT` | `restructure` | repair prompt that allows new loops and tiles |
| `SAMPLING` | `qwen` | temperature 0.7, top_p 0.8, top_k 20 |
| `GRADE_TIMEOUT` | `120` | seconds before a simulation is stopped |
| `GATE` | `static` | a full score that uses a form the trn2 compiler rejects is held at 0.95 |
| `NKI_VERDICTS` | a file | write our verdict after every level |
| `NKI_VERDICT_COMPILE` | `1` | the verdict also lowers the kernel for trn2 (needs `neuronx-cc` on PATH) |
| `USAGE_LOG` | a file | server-reported tokens per request (v7's `ask` replaces agent.py's, so its token fields are estimates) |
| `NEURON_PLATFORM_TARGET_OVERRIDE` | `trn2` | without it nki simulates trn3 |

Leave `LOOP` and `THINK` unset (their defaults: their loop, thinking off).

## What v7 changes relative to agent.py

1. **First prompt** (`PROMPT1=v2`, v7): states the exact `def` line with the reference's parameters, and
   adds a short block of real functions (`nisa.activation`, `tensor_tensor`, `tensor_scalar` with a
   per-row operand, `reciprocal`, `nl.max/sum` with keepdims), each checked to lower for trn2.
2. **Worked example by category** (`CARD=category`, v5): a matmul gets a row-mean example, a reduction a
   3-D channel mean, anything else no example.
3. **Repair messages as code** (`MESSAGES`, v2-v4): the failing line is quoted, and for known error
   classes the fix is given as lines to paste, in the model's own variable names.
4. **Matmul tiling in one message** (v5): when `nc_matmul` rejects an operand as too large, the whole
   three-loop tiling is given at once instead of one dimension per round.
5. **Repair prompt** (`REPAIR_PROMPT=restructure`, v3): "keep everything else identical" becomes "use the
   code given; restructure around new loops or tiles if the change needs them".
6. **Sampling** (`SAMPLING=qwen`, v5): Qwen3's recommended settings for thinking off; agent.py sends the
   thinking-on recipe (0.6 / 0.95).
7. **Grading** (v2, v6): a fixed copy of `grade()` (theirs raises `KeyError: 'M'` on non-matmul levels,
   level 8 included) with a 120 s timeout that scores 0.30 and says why.
8. **Compiler gate** (`GATE=static`, `gate_nki.py`): a full-score kernel using `nl.divide`, a (rows, 1)
   column as a `tensor_tensor` operand, or a loop variable as the partition index of an on-chip tile
   (outside a DMA) scores 0.95 and gets the rewrite as code; a dst whose shape differs from its source
   gets a text hint. The partition rule is the level-1 fix (below).
9. **Verdict** (`NKI_VERDICTS`, `verdict_nki.py`): after each level, VERIFIED / SIMULATOR ONLY / DOUBTFUL /
   REJECTED BY COMPILER / FAILED with a confidence, from extra hostile-value cases, a scan for
   compiler-rejected forms, and lowering for trn2.
10. **Six held-out operations** (`ops07.py`, `ops08.py`): levels 9-14, added with `nkibench.level()` the
    way their level 8 is.

## The level-1 fix (in the gate)

Qwen average-pools one channel at a time (`t[c, window]` in a channel loop), so each reduce runs on one
partition starting at partition c. The simulator and the verdict's lowering accept it; the full trn2
build rejects it ("Invalid access of 1 partitions starting at partition 1", BIR verification). Every v7
level-1 simulator solve before this fix had that form. The gate now holds such a kernel at 0.95 and
returns the loop rewritten for all channels at once (`t[:, window]`).

- Offline (`check/test_gate_l1.py`, 28 kernels whose verdict was measured with the full build on a
  seat): flags 9 of 11 that fail, 0 of 17 that build. It fires on no full-score kernel of levels 3, 4
  and 9-14; on level 2 only on kernels that fail the full build.
- Live (4090 stand-in for generation, every solve full-built + birsim on seat-115), levels 1 and 2,
  10 runs each, both conditions at once on one server:

  | runs with a kernel that builds and matches | level 1 | level 2 |
  |---|---|---|
  | with the rule | 4/10 | 5/10 |
  | without | 0/10 | 8/10 |

  Level 1: in all 4 runs the round-0 kernel was held, round 1 pasted the rewrite, and it built.
  Without the rule: 0/10 here and 0/20 in the rehearsal (4/10 vs 0/30, Fisher p = 0.002). Level 2: the
  rule fired in one run, only on kernels that fail the build; the 4 runs that failed never reached a
  full score, so 8 vs 5 is run-to-run variance. Every kernel the rule held failed the full build.
- Not yet: the 4 new level-1 kernels run on the chip; the rule on a seat-served model.
- Test: `GATE= python3 check/test_gate_l1.py` (with the exports above) -> `0 failed`.

## Levels 9-14 (ours, not the official ladder)

| level | operation | trap in the test shapes |
|---|---|---|
| 9 | row softmax | one shape scaled by 30: `exp()` overflows unless the row max is subtracted |
| 10 | layer norm | one shape shifted by +5 and scaled by 3 |
| 11 | gated SiLU, `silu(a) * b` | two inputs |
| 12 | row L2-normalize | one shape scaled by 10 |
| 13 | row log-sum-exp | one shape scaled by 30 |
| 14 | clipped gate, `clip(x, -1, 1) * y` | two inputs |

Each has a shape with more than 128 rows. They were held out when added: nothing in v6 was changed after
seeing levels 9-11, and nothing in v7 after seeing 12-14.

## Files

| file | role |
|---|---|
| `feedback_v2.py` ... `feedback_v7.py` | the layers above |
| `ops07.py`, `ops08.py` | levels 9-11 and 12-14 |
| `gate_nki.py`, `verdict_nki.py`, `hidden_eval.py` | the gate, the verdict, its extra cases |
| `check/compile_solves7.py` | full build: lower every solve for trn2 and run it in birsim |
| `check/device_check.py` | run kernels on a NeuronCore (stop the model server first: it holds all four) |
| `check/nkitool.py` | the compile helper both use |
| `pick_nki.py` | the hand-in kernel per level, re-checked |
| `check/test_gate_l1.py`, `check/fixtures/` | the level-1 rule against 28 kernels with measured full-build verdicts |
| `answers/ans_level9-14.py` | our kernels for levels 9-14 |
| `test_v7.py`, `test_requests.py` | tests (no model needed) |

**The answer kernels are never shown to the agent.** Only the checks read them: the verdict and
`pick_nki.py` use them to drop extra cases that even a correct kernel fails, and `test_v7.py` checks they
score 1.0. Level 8's answer is not published: level 8 is on the official ladder.

## Before handing in

In the same shell (the exports above; `pick_nki.py` loads v7, which reads them):

```bash
# full build of every solve (the verdict's compile step only lowers, and misses e.g. level 1's
# "Invalid access of 1 partitions starting at partition 1")
python3 check/compile_solves7.py --levels 1 2 3 4 9 10 11 --out solves attempts_v7.jsonl \
    | tee compile.txt | tail -20
# one kernel per level, ranked by simulator, compiler and extra cases
python3 pick_nki.py --out nki_kernels --compile compile.txt attempts_v7.jsonl
```

## Tests

```bash
GATE= python3 test_v7.py        # 0 failed (same exports; GATE cleared, see below)
python3 test_requests.py         # 0 failed
```

Run `test_v7.py` without `GATE`: with `GATE=static` it flags level 13's answer (two (rows, 1) tiles in
one `tensor_tensor`, which the compiler accepts). That is a known false positive of the gate; it only
fires on kernels like that one.
