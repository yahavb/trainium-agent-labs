# Gate G1: one causal Wan2.1-1.3B block on Neuron with a fixed-size KV cache

**Result: PASS.** Block 0 of the StreamDiffusionV2 `wan_causal_dmd_v2v` checkpoint, rewritten in
`tier2/block_port.py`, traced with `torch_neuronx.trace` in bf16 at the exact demo shapes, matches CPU fp32 with
cosine >= 0.99999 on `y` and both caches for 3 consecutive chunks (gate 0.999).

Run on seat-234 (trn2.48xlarge, NeuronCore 0), 2026-10-10. torch 2.9.1, torch-neuronx 2.9.0.2.15.32035,
neuronx-cc 2.27.5334.0. Raw JSON for every number below is in `tier2/results/`.

Demo v2v config (`configs/wan_causal_dmd_v2v.yaml`, 512 x 512, `--step 2`). Details in `tier2/SHAPES.md`.

## Step 3: CPU parity, rewrite vs original repo block (fp32)

`tier2/check_cpu.py`. The original `CausalWanAttentionBlock` is imported unmodified with the same layer-0 weights;
flash_attn is absent so the repo's own SDPA fallbacks run. Inputs are random latents / text pushed through the real
`patch_embedding`, `time_embedding` and `text_embedding` weights.

| Test | Cosine | Max abs error |
|---|---|---|
| Cold start, 9 consecutive chunks, `y` (worst chunk) | 0.99999999999991 | 1.1e-05 (on values up to 27) |
| Final cache after 9 chunks, K | 0.99999999999978 | 9.5e-07 |
| Final cache after 9 chunks, V | 0.99999999999949 | 0 |
| Random full cache, one call, `y` | 0.99999999999991 | 5.7e-06 |
| Random full cache, newly written K / V | 0.99999999999992 / 0.99999999999983 | 9.5e-07 / 0 |
| matmul+softmax fallback path, `y` | 0.99999999999986 | 2.3e-05 |

**Minimum cosine 0.9999999999995, gate 0.9999: PASS.** Both sides end with the same cached frames
`[0, 1, 2, 6, 7, 8]` (the original holds them in slot order `[0, 1, 2, 6, 7, 8]` after its ring wraps; mid-run the
orders differ, e.g. `[0, 1, 2, 6, 4, 5]` vs `[0, 1, 2, 4, 5, 6]`, with identical outputs).

Not gated, for calibration: against the same original output, the plain FIFO (`cat(cache[:, L:], new)`, no sink)
gives cosine 0.99999949 / max abs 0.028, and an all-zero cache gives 0.999954 / max abs 0.134. So in layer 0 `y`
depends only weakly on cache contents; cosine on `y` alone would not catch a cache bug. The 1e-5 max-abs agreement
above does.

Reference settings that differ from the demo yaml: `adapt_sink_thr = -1` (adaptive sink refresh off; it is
data-dependent control flow left to the host) and one denoising stream per cache (`total_steps = 1`), which is how
each row behaves in the demo's batched mode.

## Step 5: latency on one core and FPS estimate

`NEURON_RT_VISIBLE_CORES=0`, 5 warm-up calls, then 50 timed calls of the traced block (host call to host return,
so it includes moving ~38 MB of cache in and ~38 MB out per call).

| Loop | mean | p50 | p99 |
|---|---|---|---|
| Fixed inputs | **11.41 ms** | 11.39 ms | 11.67 ms |
| Returned caches fed back in | 12.87 ms | 12.69 ms | 17.65 ms |

An earlier run of the fixed-input loop measured mean 12.01 / p50 12.28 / p99 15.39 ms, so expect about 11.4 to
12.9 ms.

Estimate, `block_latency x 30 layers x denoising_steps_per_chunk / frames_per_chunk` with 2 steps per chunk and
4 output frames per chunk:

| Block latency used | s per chunk | s per output frame | FPS, one core |
|---|---|---|---|
| 11.41 ms (fixed inputs) | 0.684 | **0.171** | **5.8** |
| 12.87 ms (cache feedback) | 0.772 | 0.193 | 5.2 |

What the estimate leaves out: patch embedding and head, VAE encode / decode, T5 (once per prompt), scheduler math,
and Python overhead between 60 block calls. It also assumes all 30 layers cost the same as layer 0 and one call per
denoising step at batch 1.

## Open items for the next tier

- Host-side pieces not in the graph: adaptive sink refresh (`adapt_sink_threshold: 0.2`), the `t_refresh` key
  re-rotation every ~45 chunks, and the session's first call, which is a 2-latent-frame chunk (2048 tokens).
- The demo batches the 2 denoising steps as batch 2 with one cache per row; this graph is batch 1, so 2 calls per
  layer per chunk and 2 cache sets (about 2.3 GB of K/V in bf16 for 30 layers).
- Cache traffic: every call moves the full K and V through the host. Keeping caches on device, or chaining layers
  in one graph, is the obvious next latency lever.
- Cross-attention K/V of the text are recomputed every call; they are constant per prompt and can be hoisted.
