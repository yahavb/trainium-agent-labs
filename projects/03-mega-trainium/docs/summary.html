The vLLM figure isn't like-for-like (it uses two cores and includes serving overhead); it shows the stack as deployed. The one-launch kernel runs at 75% of the memory-bandwidth floor (551 GB/s achieved).

Of the 7.0 ms above the floor, about 5.9 are in the 36 layers (25.00 ms against a 19.08 ms floor, 76%) and about 1.0 in the embedding, LM head and argmax (~2.7 ms against 1.7).

Deliverable 3 · from the one-page note

What changed the work

A kernel can be 52% wrong and look fine.

Comparing against deliberately wrong references found the bug: the output matched “new token excluded” to 3e-3. That comparison is now built into the checker.

Profile before optimising.

The obvious next step measured at ~1% of the time and made things 10% slower. The profile showed TensorE starving DMA in the MLP; one tiling flag gave −5.8%.

The host overhead wasn't the uploads.

Uploads cost 0.013 ms. Holding the previous call's outputs alive cost ~6 ms per call at 36 layers. Releasing them closed the gap to the device time.

The product is the method

From a kernel to a verified, profile-optimized megakernel

A faster kernel for one model is a narrow product. The loop that found it carries over to the next model and the next chip, so we packaged it as an agent skill (skill/nki-megakernel-optimizer). The skill draws on a 724-rule NKI corpus the agent can query, and on a pitfalls list of every trap from today.

Teammate's checker, on our kernel

Symbolic proof and device test catch different bugs

We pointed nkiequiv, a symbolic equivalence checker for NKI, at the matmul core of our LM head, against a six-line NumPy spec.

Kernelnkiequiv (CPU)Trainium2 device
Our LM-head core, final structureproved 0.3 s at small tiles; 22 s at full tilescorrect; head 2.71 → 2.23 ms (−18%)
Deliberate bug: one k-tile skippedrejected names the missing term—
Our real bug: 4 accumulation groups sharing one PSUM tileproved correct in NKI semanticswrong 14.5% error

At small tiles a proof costs about 1/150 of a device check, so the agent runs it on every rewrite and sends only survivors to the device. The device gate stays, because hardware behaviour like the PSUM fault is outside any interpreter's model.
