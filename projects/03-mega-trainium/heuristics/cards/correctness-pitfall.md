# Correctness pitfalls

- Do not memset/tensor_copy a PSUM tile and then accumulate matmuls onto it on trn1/trn2. FIX: Let the first matmul overwrite (accumulate=False) and add the bias during PSUM evacuation (activation bias=, tensor_tensor).
- Remember nc_matmul computes dst = stationary.T @ moving: stationary free dim becomes dst partition dim, moving free dim becomes dst free dim. FIX: For C[M,N] = A[M,K] @ B[K,N]: stationary = A.T tile [K, M<=128], moving = B tile [K, N<=512], dst = [M, N] PSUM.
- Keep inputs of Scalar Engine log/sin/arctan/sqrt/rsqrt/reciprocal within their valid ranges (log [2^-64,2^64], sin [-pi,pi], arctan [-pi/2,pi/2], sqrt [2^-116,2^118], rsqrt [2^-87,2^97], reciprocal +-[2^-42,2^42]); use nl.sin for unbounded sine. FIX: Reduce arguments modulo 2*pi (or call nl.sin), clamp with tensor_scalar max/min, or add epsilon before log/rsqrt.
- Treat the Scalar Engine's 128 reduce registers as shared mutable state across all activation/activate2/activation_reduce calls; reset with reset_reduce before each new reduction chain and do not interleave activation_reduce with activation chains. FIX: Start each chain with reduce_cmd=reset_reduce, continue with reduce, pass reduce_res only on the last call (extra readout instruction costs a little).
- Treat Vector Engine accumulators as shared across exponential, range_select, select_reduce, tensor_scalar_reduce and tensor_scalar_cumulative; always issue reset_reduce after any instruction that ran with reduce_cmd=idle. FIX: Use reduce_cmd=reset_reduce at the start of each accumulation group and reduce for continuation; avoid interleaving other accumulating ops.
- Do not assume nc_match_replace8 and nc_find_index8 order duplicate matches the same way: match_replace8 pairs duplicates in descending position order across dst_idx columns, find_index8 in ascending order. FIX: Use one instruction consistently or sort indices afterwards.
- Expect nonzero_with_count (trn2+) to read and write only partitions 0,16,...,112; dst needs one extra free element (count) and int32 dtype, src fp32/int32 in SBUF. FIX: Place one row per 16-partition group or replicate inputs; read dst[k*16, :].
- Expect nl.var to always return a keepdims=True shape regardless of the keepdims argument. FIX: Squeeze explicitly or accept (P,1).
- Assert kernel input shapes match the tiling the kernel implements; mismatched larger inputs silently produce garbage for untouched regions. FIX: assert in_tensor.shape == (X, Y) or loop over ceil(P/128).
- Keep dynamic control flow identical on both cores of an LNC; divergent device-side branches are undefined behavior (likely runtime error). FIX: Make trip counts/conditions core-independent or pad work so both cores execute the same dynamic path.
- Do not transpose tensors that may contain NaN/Inf with an identity matmul on trn1; the NaN/Inf propagates across the output. Use trn2+ transpose mode (is_transpose=True) for bit-accurate transposes. FIX: Mask after transposing, or use DMA transpose / VectorE 32x32 transpose which are bit-accurate.
- Explicitly initialize any SBUF/PSUM/HBM tensor that is read before being fully written (accumulators, loop conditions): nl.ndarray does not zero memory. FIX: nisa.memset(dst=tile, value=0.0) or nl.zeros(...).
- When reusing a PSUM tile across accumulation groups, be explicit with accumulate=False on the first matmul of each group (or allocate a fresh PSUM tile per group). FIX: nisa.nc_matmul(dst=psum, ..., accumulate=False) for k==0, accumulate=True otherwise.
- Never use a dynamic_range loop variable in host-side Python logic (if i == 0, shape math); it is a device register. FIX: Use device-side conditionals (register compares) or peel the first iteration statically.
- Pad the contraction dim to a multiple of 2 (zeros) before using double-row FP8 matmul; both operands' second dim must be exactly 2. FIX: memset the padding slice to 0 in both stationary and moving tiles.
- For MX matmul, pack the four elements that were 128 apart along K into adjacent free-dim slots (interleave) before quantize_mx; feeding row-contiguous data gives wrong results, not an error. FIX: Use copy_data_strided-style tensor_copy to build [128, F, 4] from [4,128,F]; validate against the golden model.
- Use nki device_print (or nki.simulate) to inspect runtime values; ordinary print() in a kernel executes during compilation only. FIX: Build kernels incrementally and verify small operators in simulation mode.
- Know that nl.matmul(x, y) with transpose_x=False (or nisa.nc_matmul high-level form on [M,K]) silently inserts a TensorE transpose of x; pass pre-transposed operands to avoid hidden cost. FIX: Provide x as [K,M] (lhsT) and call nisa.nc_matmul(stationary=xT, moving=y).
- Do not take the performance guide's 'NKI only supports running a kernel on a single NeuronCore' note at face value; the LNC guide and FAQ document kernel[2] launches on two physical cores. FIX: Use kernel[2] with program_id sharding on trn2/trn3.
- Align small per-partition vectors (ones, eps, fp32 stats) to 4 bytes (align=4) when manually allocating. FIX: bufs.one_vec = sbm.alloc_stack((128, 1), dtype=io_type, align=4)
- Keep a memset-zero [P,1] fp32 bias tensor and pass it to nisa.activation calls that need a scale but no bias. FIX: zero_bias = nl.ndarray((128,1), fp32); zero_bias[...] = 0.0; nisa.activation(np.copy, x, scale=s, bias=zero_bias)
- When N*C (or H) is not a multiple of 128, use mask=(i_p < n) on load/compute/store with the full 128-partition mgrid instead of shrinking the tile. FIX: in_tile = nl.load(src[i_p, ...], mask=(i_p < n*c)); nl.store(dst[i_p,...], value=out, mask=(i_p < n*c))
- Keep two copies of a block index table: int32 with -1 sentinels for dma_copy(oob_mode.skip) and a uint32 cast (done once upfront on VectorE) for dma_transpose which requires uint32. FIX: active_blocks_sb_u32 = cast once (int32(-1) -> float32(-1.0) -> uint32(0))
- Ensure every kernel input is referenced on every core; an input consumed only on one LNC branch causes a compiler error (compute a dummy use on the other core). FIX: # K_cache_transposed and lnc=2: lnc=1 computes its own k_token_indices so token_indices stays used
- Make dma_copy src and dst slices identical in shape; handle edge tiles with min() rather than mask=. FIX: f_end = min(f_start + F_TILE, total); f_size = f_end - f_start; dma_copy(dst=t[0:p, 0:f_size], src=x[p0:p0+p, f_start:f_end]).
- Compute the reference result on CPU (tensor.cpu()) and compare with several metrics (allclose atol/rtol, max abs diff, norm of diff, cosine similarity) using dtype-appropriate tolerances. FIX: expected = ref(x.cpu()); out = kernel(x).cpu(); check allclose + max|diff| + ||diff|| + cosine.
- For multi-stage kernels, translate and validate one logical stage at a time (store the intermediate to HBM, compare to the PyTorch intermediate) before fusing stages in SBUF; test the failing stage on a single 128x128 tile. FIX: Insert temporary dma_copy of each stage output, binary-search the failing stage, then remove the debug stores.
- Use nl.device_print for runtime values; Python print() inside a kernel executes at trace/compile time and shows only static shapes. FIX: nl.device_print(...) for on-device values; print() only for shapes/patterns.
- Pass the axis that matches the actual tensor rank to nisa.tensor_reduce on 3D/4D tiles (reduce innermost first, e.g. axis=2 then axis=1); do not copy Beta-2 axis=1 examples blindly. FIX: partial (128,64,1) = reduce(axis=2); final (128,1,1) = reduce(partial, axis=1).
- Generate inputs and references on CPU, not on the XLA device, when profiling; on-device torch ops compile into extra NEFFs or get fused into the kernel's execution and obfuscate its profile. FIX: x = torch.randn(...).to(device) only for kernel inputs; everything else on CPU; use identify-neffs.py to pick the [NKI:<func>] NEFF.
- Use stride-0 (.broadcast / .ap stride 0) only on free dims or a size-1 partition dim; cross-partition replication of a non-size-1 partition needs stream_shuffle_broadcast or a matmul. FIX: Load the vector into partition 0 and call stream_shuffle_broadcast, or compute ones[128,1] @ row via nc_matmul.
- When loading one row of a tensor into a single partition, slice it as i:i+1 so the first sliced dimension (the partition dim) has size 1. FIX: nl.load(B[i_batch, i_state:i_state+1, 0:seq_len])
- Assert the simulated output contains no NaN (float) or stray 4s (int) to catch reads of memory that was never written; hardware may hide this by returning stale but plausible data. FIX: result = nki.simulate(k)(inputs); assert not np.any(np.isnan(result)); check nl.ndarray tiles are fully written, loop bounds, conditional writes.
- Do not rely on the simulator to catch SBUF/PSUM capacity overflow or overlapping-address conflicts; it allocates every tensor independently. FIX: Check footprint statically (per-partition bytes) and test on hardware; use SbufManager for deterministic layout.
- Restrict kernel bodies to the NKI meta-programming subset even though the simulator runs arbitrary Python; otherwise the kernel will fail at hardware compile time. FIX: Follow the NKI Language Guide value/container rules; test a hardware compile early.
- Treat a clean simulator run as necessary but not sufficient; some hardware constraint checks (shape limits, dtype, buffer, engine, arch version) are still missing. FIX: Report to Neuron; add explicit asserts in the kernel for tile sizes.
- Make kernel behavior depend only on its arguments (shapes, dtypes, compile-time values); global state or mutable closures can return a stale cached compilation. FIX: Pass configuration as explicit kwargs / NKIObject dataclasses.
- Treat in-place kernel outputs (cross_entropy_backward inplace=True, scatter_add input) as consumed: the input tensor is overwritten and cannot be reused afterwards. FIX: Set inplace=False or clone before the call.
- Initialize every nl.ndarray (memset, dma_copy, or compute) before reading it; allocation does not zero memory. FIX: acc = nl.ndarray(...); nisa.memset(dst=acc, value=0.0)  or use nl.zeros.
- Assert that framework tensor shapes match the shapes the kernel tiles over; a kernel written for [128,512] fed a [256,512] tensor silently leaves the remainder as garbage. FIX: assert in_tensor.shape == (X, Y) or loop over ceil(sz_p/128) tiles.
- Ensure indices within each 128-row tile are unique when using the gather-accumulate-scatter pattern; duplicate indices in a tile lose updates. FIX: Pre-sort/deduplicate indices or use the accumulating MoE unpermute path.
- Derive dimensions like H from tensor shapes inside the kernel; do not pass them as runtime scalars, because the framework materializes them as HBM tensors and shape math built on them is garbage. FIX: H = wuv_qtz_hbm.shape[0]*4 // L  instead of a runtime H argument.
