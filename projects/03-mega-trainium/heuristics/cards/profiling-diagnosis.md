# Reading a profile: diagnosis rules

- Expect each nc_matmul to appear as two ISA instructions in neuron-profile: a stationary load followed by a multiply. FIX: Keep the stationary operand fixed across consecutive matmuls (loop over moving tiles innermost) to amortize loads.
- Debug device/simulator mismatches with nki.debug(kernel, dump_dir=NEURON_RT_DEBUG_OUTPUT_DIR)(args) and breakpoint() in the kernel; for LNC2 both cores run as threads and only core_id stops. FIX: Set NEURON_RT_DEBUG_OUTPUT_DIR on the device run, then nki.debug(..., interactive=True).
- Read neuron-profile matmul rows as src=<dtype>@<addr>[strides][nums] dst=... M*K acc_flags=<f> psum_zero=<v>; acc_flags=2 means accumulator reset, and MX operands show as $MX[data,scale,start_scale_partition]. FIX: Check acc_flags on consecutive matmuls of one K-loop: only the first should reset.
- Read the DMA queue name in the profiler to learn how a DMA was generated: qGpSimdDynamic means swdge (GpSimd-generated), qSyncIO* static/sync-triggered, qSyncSpillReload* compiler spills. FIX: Click the DMA in Neuron Explorer, note the queue, then locate the trigger instruction on that engine's trace.
- Capture profiles with --enable-dge-notifs to see DGE DMA events, but expect notification-queue overflow and timeouts when the kernel issues very many DGE instructions. FIX: neuron-explorer capture -n graph.neff -s profile.ntff --profile-nth-exec=2 --enable-dge-notifs; drop the flag if execution times out.
- When TensorE looks saturated, color the Device Timeline by tensor_instruction_type and measure how much is Transpose vs Regular before optimizing matmuls. FIX: Reduce IO transposes by choosing kernel IO layout; reduce intermediate transposes by operand swap or engine choice.
- If Spill Save Bytes exceeds ~30% of Sbuf Read Bytes (or Spill Reload Bytes ~30% of Sbuf Write Bytes) in the Summary tab, fuse operators or shrink blocks. FIX: Loop-fuse producer/consumer so each tile goes load -> op0 -> op1 -> store; reduce oversized blocks.
- Drive optimization until the Summary tab shows either a compute engine >= 90% active (compute-bound) or MBU >= 60% (memory-bound); matmul kernels should also approach 100% MFU. FIX: If neither threshold is met, follow Opt #1-#10 in order: arithmetic intensity, engine idle gaps, engine efficiency, DMA efficiency.
- Diagnose each engine idle gap by the semaphore wait of the first instruction after it: a semaphore named after an engine (Vector/Scalar/GpSimd/Tensor) means a cross-engine dependency; a name starting with q means a DMA (qSyncIO* = loads, qSyncSpillReload* = spills). FIX: Engine wait -> tile the pipeline (Opt #3); DMA wait -> prefetch/overlap (Opt #4) or fix DMA efficiency (Opt #9); spill wait -> fuse (Opt #2).
- Sort the Tensor Info widget by 'Load to SBUF Repeat Factor'; any input with factor well above 1 is being reloaded and should be cached in SBUF or its loops reordered. FIX: Hoist loads, reorder loops (Mamba tutorial), or block so the reused operand stays resident.
- Recognize overhead-bound engines by repeated instructions with one-element access patterns (e.g. fp32@0x4000[1,1,1][1,1,1]) and src==prior dst; measured II ~222 ns on NC-v3. FIX: Increase free size per instruction or use a scan/fused instruction.
- Check the channels= field on vector instructions and the '128*N' operand on MATMUL; values below 128 indicate idle lanes/PE columns to recover via partition vectorization. FIX: Stack tiles across partitions; widen stationary free size to 128.
- If LDWEIGHTS (LoadStationary) shows 1 element/partition while MATMUL shows 128+ elements/partition back-to-back, swap stationary and moving operands. FIX: nc_matmul(stationary=weights, moving=vector).
- Switch the DMA view to per-engine transfers; if gaps between bars exceed the bars or hover shows tiny sizes (32 B), transfers are too small. FIX: Enlarge free/partition dims of nl.load/nl.store.
- Use the profiler search to highlight DMA activities performing transposes; if they take substantial time in a memory-bound kernel, move the transpose to TensorE. FIX: See dma-avoid-load-transpose2d-memory-bound.
- Classify the kernel by comparing dma_active_time_percent with the busiest engine: DMA ~100% and TensorE < 90% (e.g. 99.93% vs 87.28%) means memory-bound; after blocking the tutorial reached DMA 21.5% / TensorE 99.5%. FIX: Memory-bound -> Opt #9/#10 and blocking; compute-bound -> Opt #5-#8.
- When TensorE shows clear idle gaps while VectorE or ScalarE is busy at every instant (typical self-attention inner loop), optimize by instruction combining and engine rebalancing, not matmul tuning. FIX: activation with fused scale/bias, activation_reduce, DMA SBUF2SBUF transposes, trn3 VectorE exponential.
- Spill/reload DMAs have no nki_source_location; identify the spilled tensor by its name in the DMA details (e.g. inst__I-35-0:a_dst_L3_sg0000, Source [[TMPBUF]] -> Dest [SB]). FIX: Map the tensor name back to the kernel variable and reduce its live range or size.
- Upload kernel source with the NEFF/NTFF (or rely on the filename:line in instruction details) and Cmd/Ctrl-click instructions to jump to the NKI line and highlight all related instructions. FIX: Add Widget -> Code Editor; hover instruction -> Cmd+click.
- Benchmark with nki.benchmark(warmup, iters, save_neff_name, save_trace_name) and read nc_latency percentiles; validate numerics first with nki.simulate_kernel on CPU. FIX: bk = nki.benchmark(warmup=10, iters=100, save_neff_name='file.neff', save_trace_name='profile.ntff')(kernel); bk(x); bk.benchmark_result.nc_latency.get_latency_percentile(50)
- Measure DMA time as the interval-merged wall-clock time across all 16 DMA engines (dma_active_time), never the sum of per-packet durations. FIX: Use interval_merge_ns(starts, ends, t0, t1) over DmaPacket rows filtered to queue_type != 'instruction' and transfer_bytes > 4.
- Use the per-NeuronCore constants from Metadata (dma_ddr_bandwidth for DMA, tensor_engine rows*cols*2*clock for TE) when computing bounds; on trn2 these are 435 GB/s and 78.6 TFLOPS bf16. FIX: te_peak = rows*cols*2*clock_GHz*1e9; dma_bw_peak = metadata['dma_ddr_bandwidth']; break-even intensity = te_peak / dma_bw_peak (~180 FLOP/byte on trn2).
- Identify the bottleneck as the engine with the largest interval-merged active time among Tensor, Vector, Scalar, GpSimd and DMA; perfect_pipeline equals that time. FIX: engine_times = {Tensor, Vector, Scalar, GpSimd, DMA: memory_bound}; bottleneck = argmax; focus on that family's gaps.
- Decompose a DMA-bound kernel into three gaps: DMA idle (total_time - memory_bound), DMA inefficiency (memory_bound - dma_transfer_bytes/peak_bw), and excess traffic ((dma_transfer_bytes - necessary_bytes)/peak_bw). FIX: Large excess gap -> run redundant-DMA investigation first; large inefficiency gap -> DMA efficiency (descriptor size); idle gap -> do not speculate on cause.
- Decompose a TE-bound kernel into TE idle (total_time - te_active), TE underutilization (te_active - hw_flops/te_peak), and transpose overhead (transpose_flops/te_peak). FIX: Underutilization -> check tile sizes (te_inefficiency); transpose gap -> pre-transpose operands; idle -> check what MATMULs wait on.
- Bound the expected gain of any single-engine optimization by bn_speedup = total_time / max(bound_time, slowest non-improved engine time). FIX: Compute bn_speedup for each candidate bound and pick the family with the largest achievable ratio.
- Treat gaps as lower bounds on per-category overhead, not predicted savings; re-profile and recompute bounds after each change because the bottleneck engine and gap structure shift. FIX: Profile again with the same methodology, present side-by-side bounds, and pick the next investigation from the new bottleneck.
- Compute excess_ratio = dma_transfer_bytes / necessary_bytes and split the excess into input reloads (IN tensors with repeat > 1) versus spills ([VIRTUAL] transfers) before choosing a fix. FIX: Per-tensor repeat = transferred/size; flag IN tensors with repeat > 1.5; spill_bytes from [VIRTUAL] rows; localize via Instruction -> Flow -> DmaPacketAggregated filtered to source == '[[INPUT]]'.
- When both the excess-traffic and DMA-inefficiency gaps are large, fix reloads first; the excess traffic is itself made of inefficient transfers. FIX: Block/reuse to cut reloads, re-profile, then widen transfers.
- If the DMA efficiency gap (memory_bound - memory_bound_ideal) is under ~5% of memory_bound, stop optimizing transfer sizes and look at excess traffic or other engines. FIX: Switch to redundant-DMA or pipelining investigations.
- Attribute DMA to source lines using Instruction rows with hbm_read_bytes > 0 (loads) or hbm_write_bytes > 0 (stores) joined via Flow to DmaPacketAggregated, and report shape = partitions x (transfer_bytes / partitions). FIX: Group by bir_debug_info_source_location; sort by bytes; flag desc_bytes < 4096; note DPA coverage may be < 100% for swdge transfers.
- Measure TE utilization as sum(adjusted_flops)/te_active_ns against te_peak, and extract K, M, N per MATMUL source line from Instruction.operands (trailing 'K*M', N from src stride) to find undersized tiles. FIX: Re-tile lines with K<128 or M<128; verify the user is not doing intentional PE tiling first.
- Classify each MATMUL's last-finishing dependency (previous MATMUL = normal pipeline, DPA = DMA-starved, Vector = PSUM evacuation) to decide between prefetching and compute fixes. FIX: If DPA-gated share is high: enlarge/prefetch loads (row loads, double buffering); if Vector-gated: speed up PSUM->SBUF copies.
- Expect TE active time to be inflated by throttling/warm-up after idle gaps and by late-arriving weights; fix the DMA side before concluding TE is inefficient. FIX: Reduce DMA idle/starvation first (V1 -> V2: TE underutil fell from 416 to 33 us without touching matmul code).
- When perfect_pipeline exceeds both memory_bound and compute_bound (Vector/Scalar/GpSimd is the bottleneck), section the kernel logically and run windowed bounds per phase instead of whole-kernel analysis. FIX: Recompute input quantities from DmaPacket/ActiveTime/Instruction clipped to each window; attribute instructions by bir_debug_info_source_location and duration.
- Decide whether a kernel is memory- or compute-bound by comparing mm_arithmetic_intensity (FLOPs per DMA byte) with peak_flops_bandwidth_ratio, and by comparing necessary_bytes/peak_bw with hw_flops/te_peak before optimizing. FIX: jq '{intensity: .mm_arithmetic_intensity, peak_ratio: .peak_flops_bandwidth_ratio}'; if intensity << ratio, spend effort on DMA (contiguity, descriptor size, reloads), not tiles.
- For compute-bound kernels target tensor_engine_active_time_percent above 90% and compute_bound within a few percent of compute_bound_ideal (V2 reached 98.9% active, 1.8% underutil). FIX: Stop TE work when gaps collapse; remaining time is other engines or unavoidable DMA.
- Capture profiles on the 2nd execution with DGE notifications and debug info: NEURON_FRAMEWORK_DEBUG=1 (plus XLA_IR_DEBUG/XLA_HLO_DEBUG) at compile, NEURON_RT_ENABLE_DGE_NOTIFICATIONS=1 / --enable-dge-notifs and --profile-nth-exec=2 at capture. FIX: neuron-explorer capture -n $NEFF -s profile.ntff --profile-nth-exec=2 --enable-dge-notifs; check DmaPacket COUNT(*) > 0 before analysis.
- When source-level DMA attribution matters, compile the profiled variant with dge_mode none or hwdge; DmaPacketAggregated and Instruction->DPA flow links may be missing for swdge (or compiler-chosen 'unknown'). FIX: Temporarily switch dge_mode=nisa.dge_mode.hwdge for the profiling run, or accept Step-1 totals only.
- Apply fillna(0) to Summary.transpose_flops before comparing; it is NaN for kernels with no transposes. FIX: summary['transpose_flops'] = summary['transpose_flops'].fillna(0).
- Report measured bounds, gaps and attributed source lines; do not diagnose causes from a single metric or from static code reading alone, and include investigations that found nothing. FIX: Present bounds table, engine times, per-investigation findings ordered by relevance to the bottleneck.
- Read a matmul in the profiler as two TensorE instructions, load-weights (stationary) and matrix-multiply (moving), and treat gaps between them as data-wait, not compute. FIX: Zoom into gaps; hover the first instruction after a gap to see the semaphore it waits on.
- Pick kernel candidates where the profiler shows engines idle waiting on DMA in code that executes many times, and cut the graph where the region has few inputs and outputs. FIX: Use Neuron Profiler system view to find idle engines; wrap that region in a @nki.jit kernel with few tensors in/out.
- Profile the kernel with input sizes representative of the real workload, not the single-tile sizes used for correctness. FIX: Grow the driver from 128x128 x 128x512 to e.g. 4096x8192 x 8192x8192 and wrap the call in profiler.profile(...) / jax.profiler.trace(...).
- Find why an engine is idle by hovering the first instruction after the gap and reading the semaphore condition; a wait on a qSyncIO queue means a blocking input load. FIX: Hoist/prefetch the named tensor's load or reorder loops.
- Treat profiler reload warnings while SBUF usage is only ~50% as a loop-ordering bug, not a capacity limit. FIX: Reorder loops so the larger reused tensors are loaded in the outer loop (see loop-order-prioritize-largest-reuse).
- When a framework-compiled op shows sparse engine activity and very low DMA throughput at the same time, rewrite it as a fused NKI kernel. FIX: Fuse the layer in NKI with explicit tiling.
- Never benchmark with the simulator; it models no instruction latency, engine parallelism or scheduling. FIX: Profile on hardware with Neuron Explorer or run NEFFs through nrtpy.
- Expect the abs-max -> scale -> clamp -> reciprocal -> multiply quantization chain to run serially on VectorE; overlap it with another tile's work rather than trying to parallelize within one tile. FIX: Process tiles in batches of 8 so independent chains interleave.
