# Which engine runs what

- Route activation functions (exp, gelu, sigmoid, ...) through nisa.activation/activate2 on the Scalar Engine; math is always fp32 internally with free output casting. FIX: nisa.activation(dst, op=nl.exp, data, scale=s, bias=b, reduce_op=nl.add, reduce_res=rowsum) fuses scale, bias, exp and row-sum in one instruction.
- Expect tensor_tensor on all-int32/uint32 tiles to run on GpSimd (exact integer math) unless an operand is in PSUM or engine=vector is forced; nl.power always runs on GpSimd. FIX: Keep int32 index math in SBUF; avoid PSUM operands for power/int32 ops.
- In tensor_scalar use bitvec ops only on Vector Engine with integer dtypes; on trn2 the Scalar Engine only accepts (multiply,add), (multiply,None), (add,None); engine=gpsimd is only allowed for rsqrt. FIX: Leave engine=unknown, or move clamps to Vector Engine.
- Use nisa.tensor_partition_reduce (GpSimd) for cross-partition add/average/max/bitwise_or/bitwise_and reductions when a matmul-based reduction is not suitable. FIX: nisa.tensor_partition_reduce(dst, nl.add, data) (SBUF only, GpSimd cannot read PSUM).
- Pick tensor_copy's engine deliberately: Scalar casts via fp32 (lossy for int32 and unsupported on trn1 - use activation(op=nl.copy) there), Vector/GpSimd are bit-accurate when dtypes match, and PSUM operands require Vector or Scalar. FIX: Use engine=vector for exact int copies; use nisa.activation(op=nl.copy) for Scalar copies on trn1.
- Feed nc_matmul only from SBUF and expect its output only in PSUM. FIX: Evict previous PSUM results to SBUF (tensor_copy) before reusing them as matmul inputs; allocate dst with buffer=nl.psum.
- Use VectorE or ScalarE (tensor_copy, activation, tensor_tensor, tensor_reduce) to read PSUM; TensorE is write-only to PSUM and only TensorE can trigger PSUM accumulation. FIX: Accumulate on TensorE via repeated nc_matmul into the same bank; evict with ScalarE/VectorE.
- Put non-linear functions (exp, gelu, sqrt, sigmoid, ...) on ScalarE via nisa.activation and fold the preceding multiply/add into the same instruction. FIX: exp = nisa.activation(nl.exp, data, bias=bias_tile[128,1], scale=scale_tile_or_const)  # 3x faster than 3 ops
- Route two-input elementwise ops (tensor_tensor) to VectorE; ScalarE can read only one input tensor per instruction. FIX: nisa.tensor_tensor(dst, data1, data2, op=nl.add) (VectorE); use activation(scale=vec,bias=vec) only when the second operand is per-partition.
- Choose the PF-transpose engine by context: TensorE nc_transpose (128x128 via identity matmul, fastest) when TensorE is idle; VectorE nc_transpose for 32x32 blocks; DMA transpose when ScalarE/VectorE are the bottleneck; free-dim/free-dim transposes need only dma_copy or access patterns. FIX: Pick engine= in nisa.nc_transpose, or nisa.dma_transpose, per the bottleneck engine in the profile.
- Reserve GpSimd for work the other engines cannot express (iota, triangular/causal masks, custom C++ ops, software DGE) and read per-instruction costs from the ISA docs; there is no cycle rule of thumb. FIX: nisa.iota / nisa.affine_select style ops on GpSimd; keep GpSimd free if the kernel relies on swdge gathers.
- On trn1/inf2 do not expect VectorE and GpSimd to overlap SBUF work, nor VectorE and ScalarE to overlap PSUM work; on trn2 both overlap (PSUM: only if on different banks). FIX: On trn2 place concurrent VectorE and ScalarE PSUM consumers on different banks (different 2 KiB/partition regions); on trn1 do not count on the overlap.
- Keep VectorE tensor_copy/tensor_scalar operands in SBUF, in BF16/FP16, with a contiguous inner-most free dim to get the 4x Trainium2 performance mode (2x if one condition fails or one side is PSUM; tensor_tensor gets 2x with both inputs SBUF BF16/FP16). FIX: Store intermediates as bf16, avoid inner stride != 1 on VectorE copies, evict PSUM with ScalarE if VectorE is the bottleneck.
- On Trainium3, load-balance tensor_scalar and tensor_copy between VectorE and ScalarE (both support the 2x BF16 mode) by setting the engine argument. FIX: nisa.tensor_scalar(..., engine=nisa.engine.scalar) for part of the work.
- On Trainium3 compute softmax exponentials with nisa.exponential on VectorE (exp(src - max) with fused row-sum) instead of activation(exp) on ScalarE. FIX: nisa.exponential(dst, src, max_value=row_max[M,1], reduce_res=row_sum[M,1])
- Sum across partitions with a matmul against a ones vector on TensorE only when TensorE is otherwise idle; sum along the free dim with nisa.tensor_reduce on VectorE. FIX: Pick the layout so the reduction axis is the free dim for VectorE, or use TensorE for the P-dim sum in norm/softmax kernels where TensorE has slack.
- Know that broadcast_to across partitions lowers to a TensorE matmul with a ones stationary (is_stationary_onezero=True) and costs TensorE time plus PSUM eviction. FIX: Pre-broadcast once and keep the result in SBUF, or restructure so the per-partition operand is used as activation scale/bias.
- For arbitrary partition permutations or broadcasts within a 32-partition group, use nisa.nc_stream_shuffle on VectorE rather than a TensorE matmul. FIX: nisa.nc_stream_shuffle(dst, src, shuffle_mask=[...32 ints...])
- Convert engine cycle costs to time with the per-generation clocks: trn2 TensorE 2.4 GHz, VectorE 0.96 GHz, ScalarE 1.2 GHz, GpSimd 1.2 GHz (trn1: 2.8/1.12/1.4/1.4; trn3: 2.4/1.2/1.2/1.2). FIX: time = cycles / f_engine.
- Write kernels assuming Tensor, Vector, Scalar and GpSimd engines execute four independent in-order instruction streams synchronized only by compiler-inserted semaphores. FIX: Balance work so no single engine's stream is much longer than the others; keep cross-engine dependencies coarse-grained.
- Let DMA triggers go through the Sync Engine (SP) when you do not want them to perturb compute-engine instruction ordering. FIX: nisa.dma_copy(..., dge_mode=hwdge, engine=nisa.engine.sync)
- Fill all 128 partitions in every VectorE/ScalarE/GpSimd instruction; an instruction using 32 lanes costs the same as one using 128. FIX: Partition-vectorize: place independent small tiles in disjoint partition ranges and process with one instruction.
- On trn3 (gen4 sub-version 1) use nisa.exponential (Vector engine, subtracts max_value directly) for softmax exp and move the PSUM eviction to the Scalar engine; on earlier generations use nisa.activation(exp) on ScalarE and evict on VectorE. FIX: if is_trn3_b1(): nisa.exponential(dst, src, max_value=max, reduce_res=sum, reduce_cmd=...); evict_engine=nisa.scalar_engine else: nisa.activation(..., bias=neg_max, ...); evict_engine=nisa.vector_engine
- For s_prior > 256 on gen4, split the strided max-reduce between VectorE (tensor_reduce on first half of rows) and ScalarE (activate2 with reduce_op=max on the second half); for small S do it in one tensor_reduce. FIX: if s_prior > 256 and gen4: tensor_reduce(first_half); for i: nisa.activate2(dst=view_i, op=nl.copy, data=view_i, imm0=1.0, imm1=0.0, op0=nl.multiply, op1=nl.add, reduce_op=nl.max, reduce_res=qk_max[:, i], reduce_cmd=reset_reduce)
- To apply a per-column scalar (1/sum) that lives on partitions, transpose the column with 32-row vector-engine nc_transpose chunks into partition 0 and broadcast with nc_stream_shuffle, or use a single PE matmul with a stride-0 access pattern against an identity. FIX: for c in range(0, n, 32): nisa.nc_transpose(dst[0:1, c:c+32], src[c:c+32, i:i+1], engine=nisa.vector_engine); stream_shuffle_broadcast(src=dst[0:1,:n], dst=dst[:P,:n]) # or nisa.nc_matmul(dst=psum[0:128,0:n], stationary=v.ap(pattern=[[2,128],[0,128]], offset=1), moving=identity[0:n,0:n], is_moving_onezero=True)
- Broadcast a [1, F] row (e.g. gamma) across all partitions with nc_matmul(stationary=ones[1,128], moving=row[1, F]) into PSUM and consume directly from PSUM in the next op. FIX: nisa.nc_matmul(dst=g_psum[0:P, 0:F], stationary=ones_vec[0:1, 0:P], moving=gamma_sb[0:1, off:off+F]); nisa.scalar_tensor_tensor(dst=x, data=x, op0=nl.multiply, operand0=inv_rms[:,0:1], op1=nl.multiply, operand1=g_psum[0:P,0:F])
- Reduce across the partition axis with nc_matmul(stationary=ones[128,128], moving=x[128, T]); accumulate several free-dim tiles into the same PSUM and leave the accumulate flag unset consistently. FIX: psum = nl.ndarray((128, T), fp32, buffer=nl.psum); for i_d: nisa.nc_matmul(psum, stationary=ones_sb, moving=x_sq[:, i_d*T:(i_d+1)*T])
- Evict a PSUM score tile through nisa.tensor_scalar_reduce (VectorE) that scales and simultaneously produces the row max, freeing the PSUM bank earlier so the next QK matmul can start. FIX: nisa.tensor_scalar_reduce(dst=qk_sb[:, i, :], data=qk_psum_bank, op0=nl.multiply, operand0=scale, reduce_op=nl.maximum, reduce_res=row_max_kv[:, i:i+1])
- Fuse the residual add into the HBM load with nisa.dma_compute(srcs=[x, residual], reduce_op=nl.add) so it costs no Vector/Scalar/PE cycles. FIX: nisa.dma_compute(dst=hidden_out, srcs=[x_view, add_view], scales=[1.0,1.0], reduce_op=nl.add); if sharded: nisa.core_barrier(hidden_out, cores=[0,1])
- Alternate PSUM->SBUF evictions between ScalarE (activation copy, index even) and VectorE (tensor_copy/tensor_scalar, index odd); fold per-partition scale/bias into the eviction, but route full-shape scale/bias to VectorE tensor_tensor. FIX: interleave_copy(dst=out_tile, src=psum[...], scale=dequant[:,0:1], index=i)  # even->nisa.activation(copy), odd->tensor_scalar/tensor_tensor
- Pick the engine for PSUM->SBUF spills by which engine is the kernel bottleneck at that point (e.g. ScalarE once the norm is finished, keeping VectorE free for quantize_mx). FIX: nisa.tensor_copy(dst, src=psum, engine=nisa.scalar_engine)

- Map ops to engines deliberately: nc_matmul and nc_transpose on TensorE (PSUM output), activation/reciprocal/rsqrt (with fused scale/bias) on ScalarE, tensor_tensor/tensor_scalar/tensor_reduce/tensor_tensor_scan/bn_stats on VectorE, dma_copy/dma_transpose/dma_compute on the 16 DMA queues, stream shuffle / collectives on GpSimd paths.
