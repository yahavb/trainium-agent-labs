# SBUF and PSUM budgeting

- Budget for 7 usable PSUM banks (not 8) when the compiler lowers dma_transpose to a PE transpose on trn2+. FIX: Read nl.tile_size.psum_num_banks inside the kernel instead of hard-coding 8.
- Never give tensor_tensor, tensor_tensor_scan or scalar_tensor_tensor two PSUM inputs; at most one of the two tensor operands may live in PSUM. FIX: Evacuate one operand to SBUF with tensor_copy first, or accumulate both matmuls into one PSUM tile.
- Keep every GpSimd Engine instruction (iota, affine_select, nc_n_gather, local_gather, tensor_partition_reduce, nonzero_with_count, topk, sequence_bounds, rng/rand_get_state with engine=gpsimd, tensor_copy/memset/tensor_tensor on gpsimd) on SBUF operands only. FIX: Target SBUF tiles; evacuate PSUM with Vector/Scalar tensor_copy first.
- Keep the sum of live SBUF tiles per partition under nl.tile_size.sbuf_fmax_bytes (trn1 180224 B, trn2 212984 B, trn3 245752 B) and never exceed it with a single tile's free dim. FIX: Tile the free dim; use bf16 staging; read nl.tile_size.sbuf_fmax_bytes inside the kernel for portable sizing.
- Plan PSUM usage as 8 banks x 2 KiB per partition (16 KiB total, 512 fp32 per bank); a manually addressed PSUM tensor must start at a bank boundary. FIX: address=(0, bank_id*2048); limit live PSUM accumulators to psum_num_banks; evacuate promptly.
- Align manually chosen SBUF/PSUM free-dim byte offsets to at least 4 bytes (nl.tile_size.sbuf_min_align / psum_min_align). FIX: Round free offsets up to a multiple of 4 bytes (prefer larger, e.g. 64 B, for DMA efficiency).
- When hand-allocating, pass address=(partition_offset, free_offset) to nl.ndarray where free_offset is in elements of the tensor dtype and translated to bytes by the compiler. FIX: Compute per-buffer offsets explicitly (e.g. base + (i % nbuf) * tile_bytes) in a Python list of tensors.
- Expect nl.copy and tensor_copy without a pre-declared PSUM dst to produce SBUF tiles; declare a PSUM dst explicitly when needed. FIX: nisa.tensor_copy(dst=psum_decl, src=...).
- Plan SBUF residency against 28 MiB on Trainium2 (128 partitions x 224 KiB), 24 MiB on trn1 (192 KiB/partition), 32 MiB on trn3; PSUM is 2 MiB (16 KiB/partition, 8 banks of 2 KiB) on all generations. FIX: Keep live tiles well below 224 KiB per partition on trn2 (e.g. a [128, 4096] bf16 tile is 8 KiB/partition).
- Allocate tiles so their start partition obeys the hardware rule: >64 partitions start at 0; 33-64 start at 0 or 64; <=32 start at 0/32/64/96. FIX: Use partition counts of 32/64/128 and place sub-tiles at 0/32/64/96.
- Never stride along the partition dimension in one instruction access; the leading access-pattern step must equal the tensor's full free-dim element count. FIX: Use nc_stream_shuffle / transposes to rearrange partitions, or restructure the layout.
- Keep the most-minor free-dim stride at or below 16 bytes (4 fp32, 8 bf16, 16 fp8 elements) on SBUF/PSUM accesses; larger strides halve the engine's read/write bandwidth (~50% slower instruction). FIX: Reorder dims so the strided axis is not the innermost, or copy once into a contiguous layout.
- Amortize the ~60-cycle fixed cost of each tensor access request with large P and F sizes. FIX: Batch work into fewer instructions with >= 128 elements per partition.
- Keep instruction free sizes within 64K elements for SBUF operands and 4K elements for PSUM operands (bn_stats: <= 512), and remember each free axis is a uint16 size with int16 stride. FIX: Split into multiple instructions or add an outer loop.
- Reserve PSUM for TensorE outputs and evict results to SBUF with VectorE/ScalarE as soon as each accumulation group completes. FIX: tensor_copy/activation from PSUM -> SBUF immediately after the K loop; do not allocate non-matmul tensors in nl.psum.
