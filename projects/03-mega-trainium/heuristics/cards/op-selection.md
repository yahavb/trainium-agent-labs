# Where custom kernels pay off (op selection)

- Prefer nisa.nc_matmul with pre-transposed operands over nl.matmul(x, y) with transpose_x=False. FIX: Load x already transposed (K on partitions) and call nl.matmul(xT, y, transpose_x=True) or nisa.nc_matmul directly.
- To reduce along the partition axis, either transpose then tensor_reduce, or multiply by a ones[128,1] stationary tile with nc_matmul. FIX: nc_matmul(dst=psum[1,N], stationary=ones[K,1], moving=data[K,N]) gives column sums; or tensor_partition_reduce on GpSimd.
- Build transpose identities with nl.shared_identity_matrix(n, dtype) rather than ad-hoc constants. FIX: ident = nl.shared_identity_matrix(128, dtype=data.dtype); use as moving in nc_matmul(is_transpose=True).
- For SBUF-to-SBUF movement prefer nisa.tensor_copy (or nc_n_gather/local_gather for gathers) over dma_copy. FIX: Replace with nisa.tensor_copy(dst, src) (engine chosen by compiler) or a gather instruction.
- For per-partition scalar/vector broadcasts use tensor_scalar (or scalar_tensor_tensor), not a broadcast view into tensor_tensor. FIX: nisa.tensor_scalar(dst, x, nl.subtract, rowmax[(P,1)]) or scalar_tensor_tensor for (x*s)+y.
- Fuse two broadcast ops into one tensor_scalar call ((data op0 operand0) op1 operand1); one op costs the same as two. FIX: nisa.tensor_scalar(dst, x, nl.multiply, s, op1=nl.add, operand1=b).
- Use tensor_reduce(negate=True) to get -sum for free instead of a separate negate; bitvec reductions require integer dtypes and skip casting. FIX: Pass negate=True (arithmetic ops only); cast to int for bitvec reductions.
- On trn3 use nisa.exponential(dst, src, max_value=rowmax, reduce_res=rowsum, reduce_cmd=reset_reduce) on Vector Engine for softmax instead of activation(op=nl.exp). FIX: Guard with get_nc_version()==gen4; keep activation path for trn1/trn2.
- Use Vector nisa.reciprocal for small tiles (<64 elements/partition) or when precision matters; use Scalar activation(op=nl.reciprocal) for large tiles (about 8x throughput). FIX: Switch engine per tile size; combine with activation scale/bias fusion.
- Choose rsqrt engine deliberately: GpSimd (tensor_scalar(op0=nl.rsqrt, operand0=0.0, engine=gpsimd) / nl.rsqrt) is more precise but 4x slower than Scalar activation(op=nl.rsqrt); nl.rsqrt no longer accepts PSUM inputs. FIX: Evacuate to SBUF first or call nisa.activation(op=nl.rsqrt) directly.
- For ring communication use collective_permute_implicit (+ collective_permute_implicit_current_processing_rank_id) instead of explicit collective_permute pairs. FIX: Loop over iterations: rank = ..._current_processing_rank_id(it, rg); use register ALU to compute chunk offset.
- Avoid nl.divide in hot paths; compute a reciprocal (Vector nisa.reciprocal or Scalar activation) once per row and multiply with tensor_scalar. FIX: nisa.reciprocal(inv, rowsum); nisa.tensor_scalar(out, scores, nl.multiply, inv).
- Pay the MX interleave (elements 128 apart packed into quads) offline for weights and fold it into an existing strided VectorE/ScalarE pass for activations; DMA strided interleave is much slower. FIX: Reshape BF16 [512,512] as [4,128,512] and copy with a strided access pattern into [128, 512, 4], then quantize_mx.
- Write a custom NKI kernel only for (a) hot regions where the Neuron Compiler's general-purpose lowering under-utilizes hardware, or (b) operators the compiler does not support; otherwise use compiler output or NKI-Lib kernels. FIX: Pick a 'minimum cut' subgraph with few inputs/outputs; validate against a numpy reference with representative sizes before optimizing.
- Expect dense GEMM, CONV and PF-transpose to be handled well by the compiler on TensorE; spend custom-kernel effort on fusion, layout and data movement around them rather than re-implementing the matmul itself. FIX: Focus on hoisting loads, blocking all three dims, PSUM bank rotation and output coalescing.
- Treat gather/scatter/indirect patterns (embedding lookups, paged KV cache, interpolation, grid-sample) as the hardest class to make fast: they require software DGE on GpSimd, hwdge cannot gather, and before trn3 no compute engine can gather along the free dim in SBUF. FIX: Restructure data so indices select large contiguous blocks (>= 2 KiB per partition), gather 128 rows per DMA, hoist index generation, and keep GpSimd otherwise idle; consider precomputing gathered layouts on the host.
- For auto-regressive decode GEMV, keep the large weight tile as stationary ([K=128, M=128] per instruction) and the token vector(s) as moving, and batch tokens/heads into the moving free dim where possible. FIX: nc_matmul(stationary=W_tile[K,128], moving=x[K, n_tokens]); evict transposed output.
- For linear -> RMSNorm -> linear chains keep weights stationary and reduce the squared sum across partitions on TensorE; for linear -> LayerNorm swap operands so bn_stats sees features on the free dim. FIX: Apply technique 1 (operand swap) for LayerNorm, technique 2 (engine choice) for RMSNorm.
- Map softmax as: max-subtract+exp on ScalarE (activation with bias=-max), row sums on VectorE (or activation_reduce), reciprocal scaling on ScalarE, causal mask on GpSimd; on trn3 use VectorE nisa.exponential. FIX: Pipeline per 128-row tile; avoid TensorE for anything but the two matmuls.
- Avoid TensorE 'alternative uses' (transpose, broadcast, cross-partition sum, shuffles) inside matmul-bound kernels; use them freely in normalization/softmax kernels where TensorE is idle. FIX: Move reshapes to VectorE/DMA or fix layouts upstream.
- Implement sequential recurrences (Mamba prefix scan, cumulative products) with nisa.tensor_tensor_scan rather than per-timestep tensor_scalar loops. FIX: nisa.tensor_tensor_scan on VectorE (see Fused Mamba tutorial).
- Choose kernel IO tensor layouts in HBM to match the first consuming instruction's partition requirement and to keep DMAs contiguous; IO transposes are a layout decision, not a hardware necessity. FIX: Expose a transposed weight layout at the framework boundary (weight.t() once) as the tutorial's lhsT does.
- Estimate the batch size at which decode/inference becomes compute-bound as ceil(0.5 x (PeakFLOPS/MemBW) / (model FLOPs per sample / (params x dtype bytes))); below it the kernel is weight-bandwidth bound and DMA rules dominate. FIX: For batch=1 LLM decode assume memory-bound: maximize bytes/partition per DMA, use both LNC cores, keep weights bf16/fp8.
- Select the token-generation (TKG) kernel variants when batch*seqlen <= 96; otherwise use the context-encoding (CTE) variants. FIX: is_tkg = mode in (AUTO, DECODE) and B*S <= 96 and not force_cte_mode
- For RMSNorm with T >= 128 tokens use the [T(partition), H(free)] layout with one fused activation_reduce(square, add) per tile; for T < 128 (decode) use [H0, T, H1] with a ones-matrix matmul to finish the reduction across partitions. FIX: nisa.activation(sq, op=nl.square, data=x[128,T,H1]); nisa.tensor_reduce(red, nl.add, sq, axis=2); nisa.nc_matmul(dst=psum, stationary=ones[128,128], moving=red[128,T]); nisa.activation(red, op=nl.rsqrt, data=psum, scale=1/H, bias=eps_sb)
- Store RoPE channels in contiguous [first_half | second_half] order on the partition axis so rotate-half is two partition-sliced tensor_tensor ops; convert interleaved [even,odd,...] layouts with stride-2 DMA slices, or a permutation matmul only when B*heads*S <= 512. FIX: nisa.dma_copy(dst=x_sb[:half], src=x.slice(0,0,d,2)); nisa.dma_copy(dst=x_sb[half:], src=x.slice(0,1,d,2))  # interleaved->contiguous on load
- Implement rotate-half as a single nc_matmul against a signed block-circulant permutation matrix built from the shared identity when the Vector/Scalar engines are the bottleneck. FIX: rot = build_rotation_matrix(128, 1, shifts=64, dtype=nl.float16, negate=True); nisa.nc_matmul(psum, stationary=rot, moving=x)
- Do not rely on the experimental QK-swap (Q-stationary, column-tiled) MM1 path; it is hard-gated off (`return False`) due to OOB errors, and only applied to block KV with curr_sprior >= 1024 and 4 < s_active_qh <= 128. FIX: is_qk_swapped(...) -> False; keep K stationary
- Express first-order linear recurrences with nisa.tensor_tensor_scan(op0=multiply, op1=add, initial=carry) and carry the last column into the next chunk's initial. FIX: nisa.tensor_tensor_scan(dst=res, data0=A, data1=Bu, initial=scan_init, op0=nl.multiply, op1=nl.add); nisa.tensor_copy(scan_init, res[:, -1:])
- Express bilinear/trilinear 2x upsampling as a few affine-index gathers over the loaded tile (nl.mgrid with i_dst = 2*i_y+1+i_x and i_src = i_y + i_x / i_y + (1-i_x)) combined in one weighted expression, with separate expressions for faces/edges/corners. FIX: i_p,i_hx,i_wx,i_hy,i_wy = nl.mgrid[0:128,0:2,0:2,0:h-1,0:w-1]; out[i_p, 2*i_hy+1+i_hx, 2*i_wy+1+i_wx] = 9/16*in[i_p,i_hy+i_hx,i_wy+i_wx] + 3/16*in[...] + 3/16*in[...] + 1/16*in[...]
- Implement pooling/windowed reductions as a strided .ap() view that exposes the window dims last, followed by one nl.sum/nl.max over those axes, not loop-based gathers. FIX: pool_view = in_tile.ap([[H*W, P],[k*W, H//k],[k, W//k],[W, k],[1, k]]); nl.sum(pool_view, axis=[3,4])
- Generate index/offset vectors on-chip with nisa.iota(pattern, offset, channel_multiplier) rather than loading them from HBM. FIX: nisa.iota(ones_tile, [[0,1]], offset=1); even idx: odd partitions get 0xFFFFFFFF -> OOB skip
- Avoid implementing free-dim permutations as per-element nisa.tensor_copy loops (as in the transpose2d tutorial); use a strided .ap() view in a single tensor_copy or a dma_copy with transposing pattern. FIX: nisa.tensor_copy(dst=out, src=in_tile.ap([[F1*F2,P],[1,F2],[F2,F1]]))
- Choose the KV-cache update path by shape: block cache -> vectorised scatter; S_tkg==1 and B>1 (and not transposed K or B>16) -> batched vector DMA; else per-batch scalar DMA. FIX: if is_block_kv: _update_block_cache(...) elif S_tkg==1 and B>1 and (not K_cache_transposed or B>16): _update_flat_cache_batched(...) else: _update_flat_cache(...)
- Accumulate partial matmul products in PSUM via the tensor engine rather than summing partial results on the vector engine with tensor_tensor. FIX: Reuse one PSUM dst across K tiles with accumulate=(k_idx > 0).
- Supply matmul operands already in [K, M] (lhsT) layout instead of transposing tiles on-device with nc_transpose. FIX: Pre-transpose weights at load time (or ask for the transposed layout) and pass lhsT[K, M] directly as the stationary operand.
- For interleaved<->contiguous relayouts of tensors whose flattened free size fits nl.tile_size.gemm_moving_fmax, use a permutation-matrix matmul in SBUF instead of strided DMA. FIX: Build perm_matrix [d_head, d_head] via .ap() patterns ([[d_head,d_head],[1,2],[2,half_d]]) and compute nc_matmul(perm, x).
- For HBM->SBUF loads that need a transposed layout, use nisa.dma_transpose in one step rather than dma_copy followed by nc_transpose. FIX: nisa.dma_transpose(dst=sbuf[0:p, 0:f], src=hbm[0:f, 0:p]) with dst rank exactly matching the transposed src rank (NKI 0.4.0).
- Fold a preceding multiply and/or add into nisa.activation via scale= and bias= (exp(x*s), sigmoid(x+b), tanh(x*s+b)) instead of a separate tensor_scalar. FIX: nisa.activation(dst=out, op=nl.exp, data=x, scale=s, bias=b).
- Implement cumsum, cumprod, RNN-style and SSM recurrences with a single nisa.tensor_tensor_scan per tile and carry the last column as initial= to the next tile, instead of a sequential loop over elements. FIX: nisa.tensor_tensor_scan(dst, data0, data1, initial, op0=nl.multiply, op1=nl.add) computing out[i] = op0(data0[i], out[i-1]) op1 data1[i]; cumsum uses data0=ones, cumprod uses data1=zeros, initial=1.
- Replicate a bias/scale that lives in partition 0 to all 128 partitions with stream_shuffle_broadcast (nc_stream_shuffle); use tp_broadcast only for the rare column-vector (P) to row (F) broadcast. FIX: stream_shuffle_broadcast(src, dst) before the tensor_tensor/activation that consumes it.
- Express reshapes, permutes of free dims, free-dim broadcasts (stride 0) and strided slices as zero-copy views (NkiTensor methods, TensorView, or .ap()) rather than chains of nisa.tensor_copy. FIX: TensorView(x).reshape_dim(1,[F1,F2]).permute([0,2,1]).get_view(); src.ap(pattern=[[1,128],[0,512]]) for a free-dim broadcast; TensorView(cos).expand_dim(2).broadcast(2, n_heads).
- Compute mean/variance for layernorm-style ops with nisa.bn_stats over chunks of the free dim rather than separate reduce passes. FIX: nisa.bn_stats(dst=stats[0:p, nl.ds(i*DST_SIZE, DST_SIZE)], data=x[0:p, nl.ds(off, sz)]) per chunk, then aggregate.
- Prefer fused ISA ops (activation_reduce, tensor_scalar_reduce, tensor_scalar_cumulative, activate2) over an elementwise op followed by a separate tensor_reduce when the pattern matches. FIX: nisa.activation_reduce(...) producing both the activated tile and the row reduction.
- Use nisa.nc_transpose for a partition<->free transpose and an access-pattern copy (nisa.tensor_copy or dma_copy with rearranged free indices) for a free<->free transpose. FIX: P<->F: nisa.nc_transpose(dst, data). F1<->F2: copy in_tile[P, F1, F2] into out_tile[P, F2, F1] via strided indexing.
- Prefer nisa.tensor_scalar over nisa.tensor_tensor when one operand is a per-partition scalar, because tensor_tensor is 2x slower for FP32. FIX: nisa.tensor_scalar(data=x, op0=nl.multiply, operand0=vec[:,0:1]).
- Use the op0/op1 pair of nisa.tensor_scalar to perform two pipelined scalar ops (e.g. multiply then add) at the cost of one instruction. FIX: nisa.tensor_scalar(x, op0=nl.multiply, operand0=a, op1=nl.add, operand1=b)
- Implement first-order recurrences (x[t] = a[t]*x[t-1] + b[t]) with a single nisa.tensor_tensor_scan instead of a seq_len-long chain of dependent single-column instructions. FIX: scan = nisa.tensor_tensor_scan(deltaA, deltaBu, initial=0, op0=nl.multiply, op1=nl.add)
- Use (or expect) the MLP TKG path when batch_size x sequence_length <= 96 and the CTE path otherwise; override with mode=ComputationMode.DECODE/PREFILL or force_cte_mode. FIX: mlp(..., mode=ComputationMode.AUTO)  # TKG iff B*S <= 96
- Fuse the residual stream into the next projection (input + mlp_prev + attention_prev) instead of a separate add kernel. FIX: qkv(..., fused_residual_add=True, mlp_prev=..., attention_prev=...)
- Use attention_tkg for decode with s_active <= 7 and d_head <= 128, and attention_cte for prefill with sequence length > 256. FIX: attention_tkg(q,k_active,v_active,k_prior,v_prior,mask,out,cfg,sbm) or attention_cte(q,k,v,...)
- Convert interleaved RoPE layout to contiguous with a permutation-matrix matmul in SBUF only when B*n_heads*S <= 512 (gemm_moving_fmax); otherwise use strided DMA with step=2. FIX: RoPE(x, cos, sin, contiguous_layout=False, relayout_in_sbuf=(B*n_heads*S<=512))
- Broadcast a [1,H] bias across partitions with stream_shuffle_broadcast (DVE) by default, or with a TensorE ones-matmul when TensorE is idle. FIX: nkilib stream_shuffle_broadcast(bias) or matmul(ones[1,128].T, bias[1,H]).
- When a caller (e.g. ring attention) will merge partial softmax results, request unnormalized output plus raw denominators (skip_output_normalization=True with cache_softmax=True) and normalize once at the end. FIX: attention_cte(..., cache_softmax=True, skip_output_normalization=True)
- Compute sum(x^2) with nisa.activation_reduce (square + reduce-add in one ScalarE instruction) rather than a square followed by a separate reduce. FIX: nisa.activation_reduce(op=nl.square, data=x, reduce_op=nl.add, reduce_res=ss)
- Use moe_tkg when T = batch*seq <= 128 (except MX all-expert mode) and moe_cte with blockwise matmul when T > 128. FIX: moe_tkg(hidden[T,H] or SBUF [H0,T,H1], ..., output_in_sbuf=True)
