# SUBMISSION — Team 15, Syntax Error

Project 2, the kernel agent. A small model (Qwen3-8B on the seat's own Trainium2 chip) writes NKI kernels. A
checker grades each attempt and **translates the verdict into one named change**, and the loop repeats. Every
number is a **rate over n runs**, tagged **[sim]** (nki 0.6 CPU simulator) or **[device]**.

**Headline [sim]:** final C10 passed L1–L7 in **5/5 repeated runs per level** under our modified checker; L8 attention passed 0/5. The final NumPy checker accepted **9/10** levels, with A5 softmax unsolved; A7 bypassed the required tiling, so checker acceptance is not full rule compliance. Qwen's weights stayed fixed while feedback, templates, prompts, and the verification/repair pipeline changed. See [RESULTS.md](RESULTS.md) and the qualifications in [NOTE.md](NOTE.md).

The complete implementation and raw experiment archive are in [the source repository at the submitted snapshot](https://github.com/qz2930-crypto/hack-the-chip-seat73/tree/f2bda82f2fd406211cf6e9f3286b36e728b7177b). ## Agentic workflow

We delegate kernel implementation, iterative repair, and implementation of memory-reuse instructions to Qwen. A Python controller invokes a deterministic checker, sends the latest code and a specific diagnosis back to the model, keeps a short ledger when errors repeat, and stops on verification success or the run's stopping conditions. Every attempt is scored and logged. Several templates and instructions supply substantial algorithmic guidance. Claude assisted our team's supervised development; it is not an autonomous outer agent in the deployed repair loop.
