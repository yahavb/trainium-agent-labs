# 这份项目保存在哪里，以及怎么使用

你的实验容器是 **seat-85**。远程代码位于 `/workspace/projects/01-heat-rod-pde`。

ZIP 交付包是本机备份，包含代码、测试记录、模型尝试日志和结果说明。它不包含 AWS 密钥。

## 修改、保存、提交的区别

- 编辑 Python 文件：修改容器或本机里的代码。
- 运行 Python：产生答案和日志，并不会自动提交代码。
- `git commit`：在 Git 中保存一个版本，并不会自动上传到 GitHub。
- `git push`：把 Git 版本上传到远程仓库。

按你的最新要求，目标仓库是 `ChenYujunjks/trainium-agent-labs`，目标分支是 `challenge1-improvements`，同时保留本机交付包。只有远程分支实际更新后才算上传成功；本地提交不等于上传。尚未替你向比赛平台提交。

官方说明要求交付验证器、完整尝试日志和一页结果说明，没有写具体上传网站。需要正式提交时，向组织者确认接收方式，再提交这份包。

## 先看哪些文件

1. `RESULTS.md`：真实模型实验结果与局限。
2. `IMPLEMENTATION.md`：改动的原因和运行步骤。
3. `TEST_RESULTS.md`、`improvements-test.log`：自动测试记录。
4. `validation.py`：额外的独立物理验证器。
5. `improved_agent.py`：反馈记忆、容错和验证 Agent。
6. `benchmark-results`：每一道题的答案、评分、计算器调用和控制台日志。

原版的 `agent.py`、`pdecheck.py`、两个 level 文件和计算器保留，以便复现基线与比较结果。

这次修改的是 Agent 的反馈、容错和验证代码；没有训练或更新模型权重。日志可供以后分析或设计训练流程，但不代表已经完成强化学习训练。

实验中的简短输出模式在 Level 0 表现退步，因此默认关闭；需要复现实验时加 `--concise`。结果报告中的对照表记录的是该实验模式，不能当成最终默认 Agent 成功率的证明。

## 继续运行

本机 PowerShell 进入自己的容器：

```powershell
kubectl exec -it seat-85 -c app -- bash
```

在容器中启动模型：

```bash
cd /workspace
./serve.sh
```

然后在另一个连接到同一容器的终端运行：

```bash
cd /workspace/projects/01-heat-rod-pde
python improved_agent.py --level 1 --all --samples 2 --workers 2 --rounds 4 --repeat 3
```

容器被替换可能丢失远程文件，所以要保留本机 ZIP。AWS 临时凭证到期只会影响访问；可以重新运行配置脚本，隐藏输入新凭证。不要把凭证写入项目、日志或聊天。
