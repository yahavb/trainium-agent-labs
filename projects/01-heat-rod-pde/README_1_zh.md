## 问题

热量沿一根杆传播。两端保持零温度，或者其中一端绝热、热量无法从那里流失。已知初始温度分布，求此后任意时间、任意位置的温度。

每一个答案都可以**在不知道标准答案的情况下验证**。把候选解代回方程、各边界条件和初始温度分布，分别检查是否满足即可。这使其成为一个很好的 Agent 问题：检查器精确、成本低，而且不必预先知道解。

## 迭代循环

```text
controller    提出问题                                   level0_heatrod.py / level1_heatrod.py
generator     模型生成 N 个候选答案，开启采样               芯片上的 Qwen3-8B
checker       检查每个答案；评分作为奖励                    pdecheck.py
calculator    根据要求计算积分                             tool_calc.py
loop          将最佳答案对应的错误原因放进下一轮提示词      agent.py
```

满分为 1.0：**0.4** 分取决于是否满足方程，**0.2** 分对应每项边界条件，**0.2** 分对应初始温度分布。（具体得分取决于该题的边界条件。）设置部分分数是关键：如果错误答案满足方程和两个端点条件，就能得到 0.8 分，Agent 同时会获知具体缺了什么。

每一次尝试的 prompt、答案与 reward 都会追加到 JSONL 文件。**这正是强化学习训练器可直接消费的数据**。项目自然的扩展方式，是把循环的最后一步替换为训练器，让模型真正改进，而不只是重试。

## 运行时会看到什么

以下是单颗 Trainium 芯片上的 Qwen3-8B 真实输出，每轮四次尝试。**建议在运行任何程序前阅读**，了解一个有效的循环长什么样，才能区分真正的进展和无效尝试。

简单关卡在第一轮就解决，这也是 Level 0 的目的：

```text
=========== level0.1 ===========
round 0: rewards [1.0, 1.0, 1.0, 1.0]  mean 1.00  best 1.0  (8.7s)
SOLVED: u(x, t) = exp(-(3*pi)**2*t)*sin(3*pi*x)
```

更有意思的是抛物线初始形状：第一轮答案错误，检查器给出的原因促成了修正。

```text
=========== level1.3 ===========
round 0: rewards [0.0, 0.0, 0.4, 0.4]  mean 0.20  best 0.4  (28.7s)
  checker: 方程 u_t = 2*u_xx 不成立：在 x=1.087, t=0.0270 处，
  u_t - 2*u_xx = -14.88，而不是 0。t=0 时答案与所需初始形状
  相差 103.71%，要求低于 0.5%。逐项来看：
  sin(pi*x) 的系数应为 0，但你给的是 -0.8 ……
  sin(pi*x)、sin(2*pi*x) 项根本不应该出现。

round 1: rewards [0.0, 1.0, 0.4, 0.0]  mean 0.35  best 1.0  (25.4s)
SOLVED: u(x, t) = 1.032*exp(-2*(pi/2)**2*t)*sin(pi*x/2)
              + 0.03822*exp(-2*(3*pi/2)**2*t)*sin(3*pi*x/2)
              + 0.00656*exp(-2*(5*pi/2)**2*t)*sin(5*pi*x/2)
```

```text
=========== summary: level 1 ===========
  level1.1     reward 1.0 after 1 round(s)  SOLVED
  level1.2     reward 1.0 after 1 round(s)  SOLVED
  level1.3     reward 1.0 after 2 round(s)  SOLVED
  solved 3/3
```

**有四点值得注意，它们就是整个项目的关键：**

- **同一轮的奖励不同**，例如 `[0.0, 1.0, 0.4, 0.0]`。采样已开启，因此候选确实不同；如果一轮中的分数始终相同，可能没有进行有效采样，循环也无从选择。
- **0.4 代表方程与边界条件正确，而初始分布错误**。部分得分能区分错误所在，因此奖励不能只采用通过/失败二元判定。
- **Round 0 失败，Round 1 成功**，说明反馈循环真的起了作用。在 Round 0 就解决的关卡，并没有让 Agent 学到什么。
- **展示记录生成时，反馈直接打印了目标数值**，模型从消息中直接复制了 `1.032` 和 `0.03822`。当前检查器只提供方向性反馈，因此实际运行更难。参见下文“我们学到了什么”，这是全项目最重要的一点。

## 关卡设置

**Level 0** — 两端温度为零，初始形状由正弦波构成，具有精确闭式解。Qwen3-8B 首轮解决全部三题。Level 0 用来在真正的难题前验证循环确实能工作。

**Level 1** — 两类打破模型惯性的方法。

*绝热端。* 一端边界要求斜率为零，而不是温度为零。允许的波形不再是常见形式，频率减半。沿用熟悉公式的模型会满足方程和近端条件，却违反绝热端条件，得到 0.6 分。

*抛物线初始形状。* 不存在有限项的精确解；真实答案是系数需要计算的无穷级数。检查器接受初始分布误差低于 0.5% 的截断形式。实测需要三项：一项误差 3.80%，两项 0.87%，三项 0.34%。

## 我们学到了什么——这个项目真正的内容

有三次，解决问题靠的**不是更好的模型，而是更好的错误信息**。

**1. 模型给出符号推导，而不是数值答案。** 直接提问时，模型回答 `X(x)T(t)`，之后又给出带未知系数的 LaTeX 求和。两个答案作为推导都成立，但无法实际数值计算。提供一行**符合要求的完整答案示例**就解决了问题。不需要明确禁止其他形式；在仓库内另一个模型上，禁止性说明反而适得其反。

**2. 正确但无用的数字。** 仅告诉模型“初始形状相差 341%，请增加项数或修正系数”，它连续四轮停在 0.8 分，仍交替猜正负号，还保留本应为零的偶数项。现在检查器会将两个形状投影到问题本身的波形基底上，并报告**具体哪个项**有误。

**3. 公开目标答案使它不再推理。** 如果反馈打印正确系数，模型就直接复制 `1.032`、`0.03822` 来解决抛物线问题。演示可以接受，但作为奖励信号毫无价值，因为它没有推导。现在报告**只给方向**：太大、太小、缺失、符号错误、不应出现。将 `pdecheck.py` 中的 `REVEAL_COEFFICIENTS = True` 可恢复教学展示模式的数字。

### 接着引入计算器，错误也随之转移

只有方向提示时，模型开始**猜测**。实测它给出系数 `1.6, −0.8, 0.4, −0.2, 0.1`：正负交替、每项减半，然后一字不差地重复，直至轮数耗尽。它不会计算积分。

于是给它一个工具：模型写出 `COMPUTE: <expression>` 行，由 SymPy 计算并返回数值，模型再回答。**要设置哪个积分由模型决定，这才是推理，仍由模型负责；算术计算交给 SymPy。** 工具没有泄露标准答案：它只回答模型提出的问题，因此设置错误的积分仍会得到错误值，需要模型自行发现。

有了计算器，系数计算**完全正确**：`32/pi**3`、`32/(27*pi**3)`、`32/(125*pi**3)`。但是错误**转移**了，而非完全消失：模型随后将 `exp(-2*pi**2*t)` 与 `sin(pi*x/2)` 配对，指数中使用 `pi`，而对应波形实际频率为 `pi/2`。因此检查器又增加了对每一项衰减率的独立测量并指出具体问题。之后 Level 1.3 两轮解决，而 `--no-tools` 仍卡在 0.8 分。

**值得移植到自己项目中的两点：**

- *单项分数下降，不一定代表工作变差。* 模型刚把系数算对时，奖励从 0.8 降到 0.6，因为满足方程占 0.4 分，初始形状只占 0.2 分。设计奖励时要预计这种情况。
- *一次运行不等于实验结论。* 每轮四个样本时，不同运行间结果会变化：有的题原本 Round 1 就完成，有时需要三轮，偶尔还会卡住。务必报告运行次数。

## 接下来可以做什么

- **加入训练器。** 尝试日志已经是合适的格式。展示奖励随训练步数上升，并在自己的芯片上完成训练，是很有说服力的演示。
- **更难的物理问题。** 加入热源、移动边界、二维问题，或在端点不连续且收敛缓慢的初始分布。
- **减少提示。** 目前会直接提供投影公式作为方法；去掉它，测试 Agent 能否自行找到。
- **故意降低检查器质量**，测量 Agent 需要多久才解决。由此绘制的曲线最能直接证明本项目的核心主张。
