# Failure taxonomy

Every unsolved attempt in `runs/*.jsonl` (dev probes excluded), classified by the first tag the checker gave it. Generated by `python report.py --taxonomy`. Exceptions are split by whether the code unpacks `state` as a tuple (the most common single bug).

## The modes

| mode | layer | what it means | what addressed it |
|---|---|---|---|
| EXCEPTION: dict unpacked as a tuple | L1 runs | `a, b, ... = state` assigns the dict's KEYS (strings); the crash surfaces lines later | C3: the message names the unpacking line |
| EXCEPTION: other | L1 runs | NameError, TypeError and friends, reported with line, step and state | located message from C onward |
| TRUNCATED / NO_CODE | before L0 | the answer hit the token cap or had no code block | tagged separately so a budget problem never reads as a model failure |
| SYNTAX / NO_QUOTE_FN / FORBIDDEN_* | L0 static | does not parse, no quote(state), or a forbidden import or call | static gate, never run |
| CROSSED / TAKES / OFF_TICK / BAD_SIZE / FORMAT | L2 rules | an illegal quote on some step | located fix per rule; 1-tick variants caught by L5 (C4) and the state probes |
| INVENTORY_LIMIT | L2 rules | a quote that could push |inventory| past 10 | located fix; latent cases caught by the state probes |
| OBLIGATION | L3 | both sides near the touch on fewer than half the steps | located message |
| NO_FILLS (zero fills) | L4 profit | legal and present but never trades, so profit is exactly 0 | C2: the message says why nothing fills |
| LOSS_INVENTORY | L4 profit | loses holding inventory into a trend | located diagnosis (level 2) |
| LOSS_ADVERSE | L4 profit | sells into heavy bids and buys into heavy asks (level 3) | located diagnosis; C5 fill table (no effect); C6 published ideas (profit, not robustness) |
| LOSS (other) | L4 profit | loses with no single dominant mechanism | - |
| SPREAD1 | L5 (C4+) | passes at 2 ticks, fails the same markets at a 1-tick spread | C7: the layer diagnoses its own failure |
